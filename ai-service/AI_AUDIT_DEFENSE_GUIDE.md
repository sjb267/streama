# Streama AI 审核机制说明

本文档用于项目答辩时说明 Streama 的 AI 视频审核机制。核心观点是：本系统不是把整段视频直接交给 AI 黑盒判断，而是先把视频拆成可解释的审核片段，再结合画面、语音文本、投稿元数据、音频事件和文本规则进行多模态判断，最后生成风险分数、AI 建议和证据片段。

## 1. 整体审核流程

AI 审核服务的完整链路如下：

```text
streama-cloud 发送 MQ 审核任务
        ↓
ai-service 接收任务并读取视频文件
        ↓
视频预处理：抽取关键帧、提取音频、识别语音、检测声音事件
        ↓
构建审核片段 segment：按时间窗口整合画面、文本、声音和投稿信息
        ↓
调用 Qwen 多模态模型审核每个片段
        ↓
对模型结果做归一化、规则融合和业务校准
        ↓
生成文件级审核结果和视频级 AI 建议
        ↓
返回 streama-cloud 保存并在 admin 后台展示
```

这个设计的好处是：审核结果能追溯到具体时间段和证据图，管理员不需要只相信一个总分，而是可以看到“为什么这段被判为风险”。

## 2. 片段获取流程

系统不会一次性把整段视频都交给模型，而是先生成多个 `segment`。每个 `segment` 可以理解为一个审核窗口，通常包含：

| 字段 | 含义 |
| --- | --- |
| `segment_id` | 片段编号 |
| `start` / `end` | 片段开始和结束时间 |
| `text` / `window_text` | 该时间段内的语音转写文本或窗口文本 |
| `metadata_summary` | 投稿标题、简介、标签、文件名等元数据摘要 |
| `segment_frames` | 该片段内抽取出的多张代表帧 |
| `best_frame_path` | 内部使用的代表帧路径 |
| `contact_sheet_path` | 给模型看的多帧拼图证据 |
| `sound_events` | 声音事件，例如尖叫、爆炸、警报等 |
| `has_risk_sound` | 是否命中风险声音 |

片段构建大致分为几步：

1. 读取视频基础信息，例如时长、文件名、投稿信息。
2. 从视频中抽取关键帧，用于提供视觉证据。
3. 提取音频，使用语音检测和转写得到文本内容。
4. 检测音频事件，识别是否存在枪声、爆炸、尖叫、警报等风险声音。
5. 按时间窗口把画面、文本、声音事件和元数据对齐，生成审核片段。
6. 如果某些片段没有语音，也会生成视觉兜底片段，保证纯画面内容也能被审核。
7. 每个片段会准备代表帧或多帧证据图，供模型和后台审核人查看。

答辩时可以这样解释：系统先把长视频拆成多个“可定位、可复核”的片段，每个片段都有时间范围和证据图，因此审核结论不是只针对整段视频的模糊判断。

## 3. AI 审核输入

每个片段提交给 Qwen 多模态模型时，不只包含一张图片，而是组合多类信息：

| 输入类型 | 作用 |
| --- | --- |
| 画面证据 | 让模型判断视频画面是否存在违规内容 |
| 语音文本 | 让模型判断台词、旁白、字幕对应的文本风险 |
| 投稿元数据 | 标题、简介、标签、文件名也可能包含违规诱导信息 |
| 音频事件 | 对爆炸、枪声、尖叫等声音进行辅助判断 |
| 文本规则命中 | 对明显违规关键词或模式做预检查 |

模型需要返回结构化 JSON，核心字段包括：

```json
{
  "is_risky": true,
  "risk_type": "fraud",
  "risk_score": 0.85,
  "reason": "检测到疑似诈骗引导内容",
  "severity": "high",
  "policy_action": "reject",
  "evidence_modalities": ["visual", "speech_text"]
}
```

其中 `risk_score` 是片段级风险分数，`reason` 是模型给出的原因，`evidence_modalities` 表示风险证据来自画面、文本、音频还是规则命中。

## 4. 风险分数生成逻辑

### 4.1 片段级分数

片段级风险分数来自 Qwen 返回的 `risk_score`，范围是 `0~1`，分数越高表示风险越高。

| 分数范围 | 含义 | 处理倾向 |
| --- | --- | --- |
| `risk_score <= 0.30` | 低风险 | 倾向通过 |
| `0.30 < risk_score <= 0.70` | 中风险 | 建议人工复核 |
| `risk_score > 0.70` | 高风险 | 倾向拒绝或重点复核 |

服务端会对模型返回值做归一化处理，确保分数不会小于 `0` 或大于 `1`。如果模型没有给出合法分数，会进入兜底逻辑。

### 4.2 规则融合和分数校准

模型返回的分数不是最终直接使用，还会经过几类校准：

| 校准来源 | 作用 |
| --- | --- |
| 文本规则命中 | 如果标题、简介、语音文本命中明确风险规则，会提高最低风险分 |
| 音频风险 | 如果检测到枪声、爆炸、尖叫等风险声音，最低分会提升到复核区间 |
| 审核不完整 | 如果模型调用失败、图片缺失或 JSON 解析失败，使用 `0.5` 作为人工复核兜底分 |
| 零容忍风险类型 | 对诈骗、赌博、毒品、未成年人安全、自残、隐私、恐怖极端、非法交易等类型更加严格 |
| 业务语境校准 | 对影视、游戏、动画等虚构场景做降噪，避免把非真实暴力直接判成最高风险 |

几个关键规则：

- 文本规则为 `reject` 或高危时，风险分数至少提升到 `0.82`。
- 文本规则为 `review` 或中危时，风险分数至少提升到 `0.5`。
- 文本规则为 `monitor` 或低危时，风险分数至少提升到 `0.32`。
- 音频风险命中时，如果当前分数低于 `0.5`，会提升到 `0.5`。
- 审核失败、审核不完整、没有可用视觉证据时，使用 `0.5`，表示交给人工复核。
- 明确拒绝或零容忍类型命中时，分数会提升到高风险区间。
- 虚构暴力场景如果没有真实伤害证据，会被限制在人工复核区间，避免误杀。

答辩时可以强调：风险分数不是单纯由模型随意输出，而是“模型判断 + 规则兜底 + 业务校准”的综合结果。

## 5. 文件级风险分数

后台看到的文件级 `riskScore` 不是所有片段的平均值，而是该文件所有片段风险分数的最大值。

原因是审核场景更关注“是否存在任何高风险片段”。例如一个 5 分钟视频里只有 8 秒涉及违规，如果取平均值，高风险会被大量正常片段稀释；取最大值可以保证关键风险不会被掩盖。

示例：

| 片段 | 风险分数 |
| --- | --- |
| 0s-10s | `0.12` |
| 10s-20s | `0.18` |
| 20s-30s | `0.86` |
| 30s-40s | `0.10` |

文件级 `riskScore = 0.86`。

答辩时可以这样说：审核系统不是做用户兴趣推荐，不能用平均分掩盖少量违规内容，所以采用最大风险分数作为文件级风险。

## 6. AI 建议生成逻辑

系统会根据所有片段的审核结果生成 `decision_level`，再映射成后台可理解的 AI 建议。

| `decision_level` | AI 建议 | 典型情况 |
| --- | --- | --- |
| `low` | 建议通过 | 没有明显风险片段 |
| `medium` | 建议人工复核 | 存在中风险片段，或审核不完整 |
| `high` | 建议拒绝/高风险 | 出现直接拒绝风险，或多个高风险片段 |

生成建议时会考虑：

- 是否存在 `risk_score > 0.70` 的高风险片段。
- 是否存在明确 `policy_action=reject` 的片段。
- 是否命中零容忍风险类型。
- 高风险片段数量和持续时间占比。
- 审核链路是否完整，例如模型失败、图片缺失、文本缺失等。

如果审核不完整，系统一般不会直接通过，而是给出 `medium`，提示管理员复核。这是为了保证安全性优先。

## 7. 返回给后台的数据

AI 服务最终把结果返回给 streama-cloud，streama-cloud 负责保存和展示，不负责重新计算风险分数。

常见字段含义如下：

| 字段 | 含义 | 生成位置 |
| --- | --- | --- |
| `riskScore` | 文件级最高风险分数 | ai-service 汇总片段分数 |
| `riskTags` | 命中的风险类型列表 | 从风险片段的 `risk_type` 收集 |
| `hitSegments` | 审核片段列表 | ai-service 组装 |
| `hitSegments[].riskScore` | 片段级风险分数 | Qwen 结果经过校准 |
| `hitSegments[].riskType` | 片段风险类型 | Qwen 结果或规则融合结果 |
| `hitSegments[].reason` | 片段风险原因 | 模型原因 + 规则补充说明 |
| `hitSegments[].evidenceFramePaths` | 多帧证据图路径 | 从片段帧导出到 `audit-snapshot/...` |
| `itemReason` | 文件级审核说明 | 根据风险片段和报告摘要生成 |
| `aiSummary` | 视频级 AI 摘要 | 汇总各文件审核结果 |

`hitSegments` 中的证据图使用相对路径，例如：

```json
{
  "segmentId": 5,
  "startSeconds": 75.2,
  "endSeconds": 83.2,
  "riskType": "fraud",
  "riskScore": 0.86,
  "reason": "检测到疑似引导交易或诈骗内容",
  "evidenceFramePaths": [
    "audit-snapshot/videoId/auditVersion/fileId_5_frame_01.jpg",
    "audit-snapshot/videoId/auditVersion/fileId_5_frame_02.jpg"
  ]
}
```

这样 admin 后台可以在对应时间段展示多张证据图，并支持点击片段跳转到视频时间点。

## 8. 为什么需要多帧证据

单张图只能代表某一个瞬间，容易漏掉前后文。多帧证据的优势是：

- 可以覆盖一个时间窗口内的画面变化。
- 审核人能看到风险出现前后的上下文。
- 对字幕、弹幕、海报、屏幕文字等内容更友好。
- 方便答辩时解释“AI 为什么判这个片段有风险”。

当前后台展示的是 `evidenceFramePaths` 多图数组；旧数据如果只有 `bestFramePath`，前端仍可兼容显示单图。

## 9. 异常和兜底机制

AI 审核系统需要避免两种问题：误放高风险内容，以及因为模型失败导致流程中断。因此系统设计了兜底策略：

| 场景 | 兜底处理 |
| --- | --- |
| 模型返回不是合法 JSON | 标记 `audit_incomplete`，风险分数 `0.5` |
| 没有可用图片 | 标记审核不完整，进入人工复核 |
| Qwen 调用异常 | 返回人工复核结果，风险分数 `0.5` |
| 部分模态缺失 | 降低自动通过倾向，优先人工复核 |
| 文件处理失败 | 文件级结果标记失败，并给出 `processing_error` |

`0.5` 的含义不是“确定违规”，而是“不确定，需要人工看”。这比直接通过更安全，也比直接拒绝更保守。

## 10. 答辩常用问答

### Q1：为什么不直接把整段视频交给 AI 审核？

因为长视频内容复杂，直接给整段视频会导致模型输入过长、证据不可定位、结果难解释。系统先拆成多个审核片段，每个片段都有时间段、文本和证据图，能让审核结果更可追溯。

### Q2：风险分数是谁生成的？

片段级风险分数先由 Qwen 多模态模型生成，然后服务端做范围归一化、文本规则融合、音频风险融合和业务校准。文件级风险分数取所有片段分数的最大值。

### Q3：为什么文件级分数取最大值，不取平均值？

视频审核关注的是“是否存在违规内容”。即使只有几秒违规，也会影响整条视频是否能发布。如果取平均值，高风险片段会被大量正常片段稀释，所以取最大值更符合审核业务。

### Q4：为什么审核失败时风险分数是 `0.5`？

`0.5` 表示中风险和人工复核，不代表一定违规。模型失败、图片缺失或 JSON 解析失败时，系统无法可靠自动通过，所以用 `0.5` 提醒管理员人工确认。

### Q5：AI 建议是怎么来的？

AI 建议来自所有片段的综合结果。系统会看是否存在高风险片段、是否命中零容忍类型、是否有明确拒绝动作、审核是否完整，再映射成通过、人工复核或拒绝。

### Q6：后台展示的证据图有什么作用？

证据图让审核人不用重新从头看视频，可以直接定位到风险片段。多帧证据还能看到片段内的上下文，降低单帧误判。

### Q7：streama-cloud 会不会重新计算 AI 分数？

不会。风险分数和 AI 建议由 ai-service 生成，streama-cloud 负责保存 `riskScore`、`hitSegments`、`riskTags` 等结果，并在后台展示。

### Q8：这个方案相比关键词审核有什么优势？

关键词只能处理文本，容易漏掉画面、声音和上下文。本系统结合画面、语音文本、投稿信息、音频事件和规则校准，能覆盖更多视频风险场景，同时保留证据方便人工复核。

## 11. 一句话总结

Streama 的 AI 审核流程可以概括为：先把视频拆成可定位的审核片段，再用多模态模型结合画面、文本、声音和规则生成片段级风险，最后汇总成文件级风险分数和视频级 AI 建议，并把证据图展示给后台审核人辅助决策。
